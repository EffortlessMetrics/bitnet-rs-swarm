# v0.3.0 Preview Release Notes

Status: Draft source-promotion input
Owner: BitNet-rs maintainers
Created: 2026-06-05

These notes describe the intended v0.3 usable-preview posture for a future
source-repo preview tag. They do not tag, publish, sign, or release anything
from the swarm repository.

Before any public release, the source-promotion packet must re-check the live
support matrix, model coverage matrix, receipts, CI state, and release-ready
guard. If these notes disagree with those sources, the narrower source wins.

## Release Posture

BitNet-rs v0.3.0 preview is intended to be a small, honest local-inference
preview:

- build or install the `bitnet` CLI;
- inspect model and device support with `bitnet model status`;
- fetch or verify exact supported-preview models;
- run a bounded local answer path for exact supported-preview rows;
- explain receipts with `bitnet receipts explain`;
- generate issue context with `bitnet support bundle`;
- understand what is supported, candidate, diagnostic, or unsupported.

This is not a production release.

## What Works

The preview target includes these surfaces when exact proof rows are current:

- official Microsoft BitNet 2B I2_S/QK256 local-answer paths for exact supported
  CPU, CUDA, or Apple CPU/NEON rows;
- dense SLM local-answer paths for exact supported rows such as scoped Qwen2.5,
  Qwen3, and Apple CPU/NEON entries named by the support matrix;
- `bitnet model status` as the front door for supported, candidate,
  diagnostic, and unsupported rows;
- receipt explanation with model coverage row, tier, route, backend, fallback,
  speed state, server state, claim boundary, and warnings;
- support bundles suitable for GitHub issue triage.

The authoritative row list is [Support Matrix](../../status/SUPPORT_MATRIX.md).

## Supported Models

Supported-preview model families are limited to rows named by the support
matrix and matching device matrices:

- Official Microsoft BitNet 2B I2_S/QK256, exact rows only.
- Qwen2.5 0.5B dense SLM, exact rows only.
- Qwen3 0.6B dense SLM, exact bounded CUDA rows only when the matrix keeps them
  promoted.
- Apple M4 CPU/NEON dense SLM rows, exact model IDs only.

Candidate and diagnostic rows remain visible in status output but are not
supported local-answer paths.

## Supported Devices

Device support is exact-label only:

- `cpu` and exact CPU labels where accepted CPU answer receipts exist.
- `nvidia-rtx-5070-ti-cuda` for exact CUDA rows in the CUDA capability matrix.
- `apple-m4-cpu-neon` for exact Apple M4 CPU/NEON rows in the Apple capability
  matrix.

Generic GPU support is not part of the preview claim.

## Performance Posture

The preview does not claim speedup by default.

`speedup_claim=false` remains correct unless an exact benchmark-qualified
receipt and support row promote speed for the same model, device, route, and
profile. CUDA execution, SIMD dispatch, Metal visibility, or accelerator
detection is not a speedup claim.

## Server Posture

CLI readiness is separate from server readiness.

Server readiness is exact-profile only. A server row must identify the model,
device, backend, route, endpoint, streaming mode, quality gate, receipt, and
support-matrix promotion. Broad OpenAI-compatible serving, streaming,
concurrency, production deployment readiness, and other model families are not
included unless exact rows prove them.

## What Does Not Work Or Is Out Of Scope

- Production deployment support.
- Generic GPU support.
- Broad OpenAI-compatible server support.
- Speedup without benchmark-qualified receipts.
- Full accelerator residency without residency receipts.
- Claim inheritance between dense SLM proof and BitNet QK256 proof.
- Claim inheritance between CUDA, Apple CPU/NEON, Metal, MPSGraph, Neural
  Engine, OpenVINO, A770, ROCm, WGPU, or Vulkan.
- New unproven model families.
- Release, publish, signing, or tagging from the swarm repository.

See [Known Limitations](../../status/KNOWN_LIMITATIONS.md) for the longer
boundary list.

## How To Try The Preview

Start with:

```bash
bitnet model status
bitnet model fetch <supported-model>
bitnet model verify <supported-model>
bitnet ask --model <supported-model> --device <supported-device> "What is 2+2?"
bitnet receipts explain --latest
bitnet support bundle --latest --device <supported-device> --format json
```

Use [Quickstart](../../quickstart.md) and [Support Matrix](../../status/SUPPORT_MATRIX.md)
for the current supported-preview path.

## Issue Reports

When filing an issue, include:

```text
bitnet version
model id
device label
requested backend
selected backend
selected route
fallback_used
quality gate result
speedup_claim
server_ready
server_ready_scope
receipt path
support bundle JSON
```

Do not include secrets, credentials, private model files, tokens, or unrelated
logs. Use [Support Triage Guide](../../tutorials/support-triage.md) to decide
which fields matter for common failures.
